# Архитектура проекта online-store (FSD 2025)

## Слои и их ответственность

- **app** – точка входа приложения, глобальные провайдеры (router, pinia, i18n, toast), стили и базовая конфигурация запуска.
- **pages** – конечные пользовательские страницы. Формируют layout и подключают необходимые виджеты/фичи/сущности.
- **widgets** – составные блоки страниц (например, хедер). Собирают несколько сущностей и фич в единый UI.
- **features** – прикладные сценарии пользователя (авторизация, управление корзиной, оформление заказа).
- **entities** – доменные сущности (пользователь, продукт и др.) со своими моделями и API.
- **shared** – переиспользуемая инфраструктура: UI-компоненты, библиотеки, API-клиенты, глобальные типы.

Каждый слой разделён на срезы (*slices*): `user`, `category`, `product`, `post`. Внутри срезов действуют сегменты (*segments*):

```
ui/     → визуальные компоненты
model/  → состояние и хранилища
api/    → сетевые запросы и клиенты
lib/    → прикладные утилиты
index.ts → public API среза
```

## Примеры срезов и сегментов

- `features/product/model/cart.store.ts` – модель фичи «корзина».
- `entities/product/model/products.store.ts` – модель доменной сущности «продукт».
- `pages/user/ui/LoginPage.vue` – страница входа.
- `widgets/user/ui/AppHeader.vue` – общий хедер, использует сущность пользователя и навигацию.

## Правила импортов и зависимостей

- Слои могут зависеть только от уровней, расположенных ниже по иерархии: `app → pages → widgets → features → entities → shared`.
- Срезы не пересекаются напрямую: `features/product` не импортирует `features/user` напрямую – взаимодействие идёт через `entities` или `shared`.
- Общие утилиты и типы лежат в `shared`. Они не могут зависеть от других слоёв.
- Все импорты выполняются через публичные API (`index.ts`) с использованием алиасов: `@app`, `@pages`, `@widgets`, `@features`, `@entities`, `@shared`.

## Public API слоёв

- `@app` – экспорт `App` и `setupApp` для инициализации приложения.
- `@pages/<slice>` – страницы конкретного среза (`HomePage`, `CatalogPage` и т.д.).
- `@widgets/<slice>` – крупные UI-компоненты (`AppHeader`).
- `@features/<slice>` – модели, API и утилиты фич (`useCartStore`, `useAuth`).
- `@entities/<slice>` – доменные модели и типы (`useAuthStore`, `useProductsStore`).
- `@shared` – общий слой (API-клиенты, базовые UI-компоненты, типы, хелперы).

## Глобальные алиасы

- `vite.config.ts` – настраивает алиасы для рантайма Vite.
- `tsconfig.app.json` – дублирует алиасы для TypeScript, чтобы IDE понимала импорты.

Алиасы всегда ведут к публичным API слоя (`index.ts`). Пример импорта страницы: `import { CatalogPage } from '@pages/category'`.

## Хранение типов

- Локальные типы, привязанные к срезу, хранятся внутри сегмента (`entities/product/model/types.ts`, `features/product/model/types.ts`).
- Глобальные универсальные типы — в `src/shared/types/` и экспортируются через `@shared/types`.
- Импорт типов происходит также через публичные API: `import type { Product } from '@entities/product'`.

## Ключевые файлы слоя `app`

- `src/app/App.vue` – корневой шаблон приложения, подключает виджеты и глобальные стили.
- `src/app/setup/setupApp.ts` – функция, которая регистрирует провайдеры (pinia, router, toast, i18n) и запускает начальную загрузку стора.
- `src/app/providers/*` – изолированные фабрики провайдеров. Каждый провайдер экспортирует простую функцию (`createAppRouter`, `createPiniaProvider`, `registerToast`, `registerI18n`).
- `src/app/styles/main.css` – точка входа глобальных стилей (Tailwind + кастомные токены).

## План миграции старого кода

1. **Слои и алиасы** – перевести существующие модули в новые директории, настроить алиасы в Vite/TS.
2. **Разделение по сегментам** – файлы распределить на `ui`, `model`, `api`, `lib`, создать `index.ts` для публичных API.
3. **Типы** – перенести доменные типы в соответствующие `model/types.ts`, общие типы – в `shared/types`.
4. **Переход на публичные импорты** – заменить все `@/...` на алиасы нового слоя.
5. **Инициализация** – вынести провайдеры (router, pinia, toast, i18n) в `app/providers/`, добавить `setupApp` для запуска стора/маршрутизатора.
6. **Документация** – обновить README/STRUCTURE.md с описанием архитектуры.
7. **Постепенная доработка** – переносить оставшийся функционал (виджеты, фичи) в новые сегменты, избегая зависимостей вверх по слоям.

Следуя этому плану, можно безопасно мигрировать существующий код, не нарушая работу приложения.
